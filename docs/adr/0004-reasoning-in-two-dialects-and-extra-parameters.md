# Reasoning in two fixed dialects; what a model needs beyond them goes in the Extra parameters

Providers do not agree on how to ask a model to reason, and on the same Provider each model family can want something different: on TensorX some models take OpenAI's `reasoning_effort` but refuse some of its levels, others want their own key under `chat_template_kwargs` and silently ignore `reasoning_effort`. OpenRouter is the exception, because it takes one `reasoning` object and translates it for each model itself. The evidence and the options weighed are in Takku's ADR 0009; Dimmela takes the same decision.

Dimmela therefore knows two dialects and no model names. The Reasoning menu in Settings › Post-processing (model default, off, low, medium, high) is sent as `reasoning.effort` to OpenRouter, recognised by its host, and as `reasoning_effort` to every other Provider; with the model default neither is sent. Whatever a model needs beyond that goes in the **Extra parameters**: a JSON object written by the user and added to every Post-processing request, *Test Connection* included. Any key is allowed except `model` and `messages`. Each top-level key replaces what Dimmela would send for it, menu included, with no deep merge. Settings saves them only when they are a JSON object without those two keys, in a field with no smart quotes. Only the request body is covered, no HTTP headers.

## Consequences

- When the Provider refuses a request (400 or 422) and Settings sets reasoning or Extra parameters, the error adds what was sent beyond a plain request (the reasoning level, unless the Extra parameters replaced it, and whether there were Extra parameters), never the parameters' content, since the message also goes to the log. The Provider's message is cut at 300 characters so that this stays readable in the notification. No automatic retry without them: a mistake in what the user typed must show. As for any Post-processing failure, the Transcript is pasted.
- Reasoning slows Post-processing down, and it sits between the end of speech and the paste: the 30-second limit still applies, and a model that reasons too long gives the Transcript instead.
- The reply is read with the reasoning left out: `reasoning_content` is ignored, Mistral's list of chunks keeps the `text` ones, and anything up to the last `</think>` or `</thinking>` is dropped. Getting this wrong would paste the reasoning into the user's app.
